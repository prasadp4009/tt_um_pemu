TEMPO — Timing-Exact Multi-Protocol Observer

The debugger's chip.

A programmable protocol-emulator ASIC with an independent on-chip logic analyser, for the Jane Street Protocol Emulator ASIC Competition (Tiny Tapeout, IHP 130 nm SG13G2 / CMOS5L, 6×4 tiles, submission deadline 18 January 2027).

TEMPO does not hard-wire a protocol. It executes firmware in a 32-bit timed instruction set (TEMPO-32 ISA v0.2 + v0.3 note): every instruction carries a delay field, pin effects land on exact cycles, WAIT returns the cycles actually elapsed, and CAP atomically snapshots {timestamp, pins}. Change the program, change the protocol — no re-spin. Next to the engine sits the Observer, an independent trace block whose memory the engine cannot read, so it can characterise the bus — including the engine's own output.

Architecture

  • PE core (u_pe) — TEMPO-32 engine: 16 × 16-bit GPRs, 20 special registers, ALU + flags, CALL/RET stack, TX/RX FIFOs (16 × 16-bit each), 9-bit PC (v0.3).
  • Observer (u_obs) — EDGE / PATTERN / PULSE triggers, prescaler, watermark, 204-entry trace SRAM (u_tmem). Configured by firmware via MSR or by the host via WR_CFG; read only by the host via RD_TRACE.
  • Host port (u_host) — 2-wire framed serial, autobaud, ACK/NACK, on ui[0] (HP_RX) / uo[0] (HP_TX).
  • Pin fabric (top level) — per-pin direction (PDIR), open-drain + pull-up (PMODE), masking (PMASK), 2-FF input synchronizer.
  • SRAMs — u_imem 512 × 32-bit instruction memory; u_tmem 1024 × 8-bit trace memory.

Instruction word

Timing contract

Every instruction executes in 1 + d cycles; PGET reads the 2-FF-synchronised pins (2-cycle architectural latency, accounted for in every firmware image); SLEEP is exactly 1 + imm13 cycles; a WAIT whose condition is true exactly at the deadline counts as satisfied (elapsed = timeout, no TIMEOUT sticky); HLT gates PE clocks while the Observer and timestamp keep running.

The honest timing note. The slow-corner setup violation is the one genuine silicon-risk item, and it is characterised, not hidden: at the slow corner the IMEM fetch-path net cannot meet a 20 ns cycle (worst slack −2.824 ns ⇒ slow-corner fmax ≈ 43.8 MHz). Run at ≤ 43.8 MHz if setup must be guaranteed at the slow corner; 50 MHz is met with margin at typical and fast corners only. The competition sets no clock target. A timing-closure redesign is out of scope for this submission.

Pin functions: ui[0] = HP_RX, uo[0] = HP_TX, uio[0..7] = PIN0–PIN7 (protocol pins, per-pin direction via PDIR, open-drain via PMODE). Other ui/uo bits are unused/tied. Example SPI map: SCLK = PIN2, MOSI = PIN3, CS# = PIN5, MISO = PIN0. USB map: D+ = PIN0, D− = PIN1.

ISA reference (summary)

24 opcodes: PSET PSETR PGET PMASK PDIR PMODE (pins), SLEEP WAIT CAP (timing/measurement), MOV LDI (data), PUSH PULL (host FIFOs), MRS MSR (special registers), ADD/SUB AND/OR/XOR SHL/SHR CMP (ALU + flags), JMP DJNZ CALL/RET, HLT, EVT. v0.3: JMP/CALL target9 = instr[20:12], DJNZ target9 = instr[16:8]; PC 9 bits (0–511). Defined behaviours: illegal opcodes 24–63 = NOP + CONFIG_ERR; CALL on a full stack drops the call + CONFIG_ERR; RET on an empty stack = NOP + CONFIG_ERR; unallocated special registers read as zero; SPI mode 3 returns 0xFFFF (unsupported).

SPI master: init + command loop (excerpt from firmware/spi/spi.asm)

; TEMPO-32 SPI master -- mode 0, 1 MHz; 50 MHz core -> 50 cycles/bit.
; Host words: 0x0001 TRANSFER (PULL N, then N data words; PUSH rx bytes,
;   then 0x0000 status, evt 0) · 0x0003 SET MODE (unsupported -> 0xFFFF)
;   · 0x00FF HALT · other -> 0xFFFF.
; NOTE: pdir 0x01 (not 0xFF) for R_ONE -- idle levels are committed
; BEFORE pdir enables the drivers, or CS# glitches low for ~2 cycles.
        pdir 0x01
        pmask 0xFF
        pset 0x01, d=4
        pget r15                 ; r15 = 1 (preserve forever)
        pmask 0x2C               ; pin ops touch only pins 2,3,5
        pset 0x20                ; idle levels first: CS#=1, SCLK=0, MOSI=0
        pdir 0x2E                ; THEN drive SCLK(2), MOSI(3), CS#(5)
        xor r0, r0, r0
        ldi r9, 4
        ldi r14, 0x0100
        sub r14, r14, r15        ; r14 = 0xFF
        ldi r12, 8
; RACE FIX 2026-09-27: every PULL is preceded by an RXNE wait.
cmd_loop:
        jmp cmd_have, rxne
        jmp cmd_loop
cmd_have:
        pull r6
        cmp r6, r15              ; 0x0001 = transfer?
        jmp do_xfer, z
        cmp r6, r13              ; 0x0003 = set mode?
        jmp do_mode, z
        cmp r6, r14              ; 0x00FF = halt?
        jmp do_hlt, z
        jmp do_unk
; bit_loop: 17 fixed insns + SLEEP16 + SLEEP3 + SLEEP14 = 50 cycles/bit.
; Measured: SCLK 50 x14 zero deviation, 58-cycle period at byte
; boundaries, 408 cycles/byte.

How to use the chip

  1. Reset. Assert rst_n for a known state. ena = 0 = PROG mode; ena = 1 = RUN mode.
  2. Load. Over the host port (autobaud framed serial, ACK/NACK): LOAD_IMEM writes {addr16, data…} frames (≤ 63 words/frame); VERIFY_IMEM reads the image back byte-identical. LOAD/VERIFY are rejected while the PE runs — halt first, or load before the first GO.
  3. Configure (optional). WR_CFG sets pin mux, Observer trigger mode/masks, prescaler, watermark. Firmware can also configure the Observer via MSR; either way, the PE never touches trace memory.
  4. Run. GO releases PE reset with PC ← 0. The host pushes command/data words (WR_RXFIFO) and pops responses/events (RD_TXFIFO). Firmware images are command-driven and signal completion with evt 0.
  5. Observe. RD_TRACE reads trace entries {timestamp, pins} plus OBS_PTR. RD_STATUS returns {PE_RUNNING, PE_HALTED, TIMEOUT, TX_EMPTY, RX_FULL, TRACE_WM, TRACE_FULL, CONFIG_ERR}. HALT_REQ requests a clean stop; re-GO restarts from PC 0.
  6. Reload. Program reload on reselect is supported: halt, reload via LOAD_IMEM, re-verify, GO. No power cycle needed.
  7. Clock. Nominal 50 MHz; for guaranteed setup across all corners, run at ≤ 43.8 MHz. Timestamp resolution is one clock cycle at whatever clock you run.

The ASIC is not fabricated yet. “Hardware-proven” means proven on the Zybo FPGA port of the same RTL + firmware, through three stages: (1) golden model (cycle-exact ISA simulator) with protocol-specific checkers; (2) cycle-exact RTL co-sim replay (SPI 855/855, UART 8,747 cycles, USB merged 6,297 cycles; 11/11 co-sims overall); (3) Zybo hardware runs checked by milestones + a run signature. Honest limitations

Bounded, characterised behaviours — full evidence in CHARACTERIZED_LIMITS.md and OPEN_ITEMS_AUDIT.md (2026-10-29 audit). After that audit, no unhandled chip-functionality bug remains; the functionality-affecting list is exactly: the slow-corner timing guidance, the T17 decision item, and the limits below.

  • CAN DLC ≤ 2. No data RAM; all 16 GPRs allocated mid-frame. DLC > 2 arguments are consumed/discarded, PUSH 0xFFFF. IMEM-512 does not lift the cap; redesign out of scope.
  • UART TX host starvation blocks. No timeout, no 0xFFFD abort on this path (the abort is a safety net for pulls that bypass the RXNE wait, which normal operation never does). Recovery: supply the missing word, or host reset/reload. Firmware-demo limitation, not a PE bug.
  • WAIT long timeouts not implemented (T17, decision item). tsel 0 → 256, tsel 1 → 4096; tsel 2/3 fall back to 256/4096 + CONFIG_ERR. Largest elapsed ever written is 4096 — no overflow can occur as built. Saturating at 0xFFFF is not implemented and not claimed; the standing recommendation (rule tsel 2/3 out of the submitted ISA, chain tsel=1 waits) is for the ISA lead.
  • SPI at 125 MHz: observed, not guaranteed. Proven point is 50 MHz. Baseline failed deterministically at 125 MHz (0x13); the 512 build passed twice with the identical signature, but the baseline failure was never root-caused and no fix is claimed.
  • Observer PULSE mode watches pin 0 only. Top level ties pin-select to 0. EDGE/PATTERN unaffected. Trace saturates at 204, never wraps; TRACE_WM sticky, cleared only by OBS_CLR.
  • Observer hardware capture is the remaining score item, not a chip bug. Sim/co-sim only (bench tb_observer, 35 checks). No hardware trace-SRAM capture has ever been demonstrated: the Zybo harness has no RD_TRACE path (loader: LOAD / VERIFY / GO / TRANSFER / RD_TXFIFO only). The silicon path exists (host 0x07 RD_TRACE, MSR Observer config) but needs a scoped harness build. No board capture is claimed anywhere on this page.
  • USB device stack / 10BASE-T. Merged USB TX+RX proven; a full device stack is firmware work beyond the shipped image. 10BASE-T is not feasible on-chip and is not claimed.
